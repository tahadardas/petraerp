## 0. تفويض واضح بالعمل المتواصل

أنا مالك Petra ERP وأعتمد **التنفيذ المتتابع التلقائي** لواجهات React/Tauri بكامل النطاق الإنتاجي الذي تدعمه عقود API الحقيقية، وليس مجرد عمل تصميم أو وضع خطة. **لا تتوقف بعد كل شاشة، ولا ترسل لي سؤالًا روتينيًا للموافقة على الألوان أو ترتيب الحقول أو الانتقال للمرحلة التالية.** نفّذ ← اختبر ← أصلح ← وثّق ← Commit على فرعك ← انتقل تلقائيًا إلى المهمة التالية، حتى تغطي كل الشاشات القابلة للتنفيذ. قرار العمل المتواصل هذا يُحدّث بروتوكول «موافقة المالك بعد كل شاشة» الموجود في SRS **في نطاق الأعمال الأمامية غير التخريبية فقط**؛ أما القواعد المالية، والترحيلات، والصلاحيات، والهجرات، والنسخ، وعمليات الإنتاج عالية المخاطر فلا يتجاوزها هذا التفويض.

لا تكتفِ بشرح كيف ستعمل؛ نفّذ الشيفرة والتكامل والاختبارات. لا تَعِد بعمل لا تقدر بيئة التشغيل عليه. إذا بلغت نافذة الجلسة أو الميزانية حدًا لا يسمح بالاستمرار، أنشئ **نقطة استئناف تنفيذية صادقة** بكل ما اكتمل وما تبقى وأول أمر للمواصلة؛ لا تقل «اكتمل البرنامج» ولا تعتبر التوقف القسري نجاحًا. عند عودة إمكانية التنفيذ استأنف من نقطة الاستئناف، لا من الصفر.

**الحالات التي يجوز أن توقف تنفيذ العملية المعنية فقط**: هجرة بيانات إنتاج، حذف نهائي، تعديل قواعد محاسبية أو ترحيل، فتح صلاحية زائدة، استخراج أسرار، قرار أمني غير محسوم، أو API غير موجود يلزم لتشغيل وظيفة بعينها. وثّق العائق وأرسل Backend handoff إلى Claude وتابع شاشة مستقلة أخرى دون انتظار. إذا كان العائق يشمل كل المهام المتبقية، اختم بتقرير BLOCKED لا ادعاء اكتمال.

## 4. التفاعل على طريقة المحاسب — توافق منطق الأمين 10

- **الفأرة:** زر يمين ديناميكي في حقول القوائم وجداول الحسابات والمواد والفواتير والسندات والتقارير. العمليات بحسب نوع الخلية وحالة المستند والصلاحية: نسخ خلية/سطر/نطاق، لصق، إضافة/حذف سطر، فتح بطاقة الطرف/الحساب/المادة، فتح مستند المصدر، فتح القيد، كشف الحساب، اختيار سعر، تخصيص أعمدة، تصدير، طباعة. لا تعرض إجراء غير مدعوم من Backend كزر يعمل.
- **لوحة المفاتيح:** Enter/Tab للتقدم بالحقل التالي، Shift+Tab للعكس، الأسهم داخل الجداول حسب RTL/LTR، F3 للقائمة/البحث حيث مثبت في منطق الأمين، Esc للإغلاق الآمن، F2 لتعديل خلية حيث ملائم، Ctrl+C/V للنسخ واللصق، Ctrl+K للبحث الشامل، Ctrl+W لإغلاق تبويب غير متسخ، Ctrl+Tab للتبديل، Ctrl+S للحفظ وفق صلاحيات وسلوك النظام. **انشر Shortcut Registry موحدًا وقابلًا للتعديل ولا تفترض اختصارات أخرى من الأمين بلا دليل**. تجنّب اختصارات النظام المتعارضة.
- **50 سطرًا:** عرض 50 سطرًا جاهزًا في مدخلات الفواتير والسندات ذات السطور، نمو تلقائي عند الكتابة؛ يُرسل فقط المملوء، دون تحميل 50 سجلًا ماليًا فارغًا للخادم.
- **النقرة والـFocus:** لا يفقد المحاسب موضعه عند تعديل الصف أو وصول البحث أو ظهور Popup؛ إعادة التركيز الصحيح بعد الاختيار/الإلغاء؛ استخدام keyboard-first فعلي دون متاهة تنقل.
- **الاختيارات:** يمكن البحث بحرفين، بالرمز أو جزء الاسم، `*` لإظهار الكل عندما يسمح API، debouncing وAbortSignal وpage limit، منع N+1، والعمل بالبيانات المصرح بها فقط.
- **إدخال مالي:** مرّر مبالغ Decimal Strings كما يطلب العقد؛ عرض فاصل تجميع كل 3 أو كل 2 بحسب خيار المستخدم، والأرقام الإنجليزية حسب قراره، والتحويل من الأرقام العربية عند الإدخال؛ لا تستخدم `Number`/`parseFloat` للحسابات المالية، ولا تخلط فاصل التجميع بالمنازل العشرية. لا تحسب الأرصدة النهائية في React.
- **المستند:** كل حقل يشرح سبب طلبه؛ لا رسائل «عبّئ كذا» دون سياق. استخدم default من نمط المستند ثم سياسة الشركة ثم صلاحية الفرع، ويطبّق API قاعدة الحسم النهائية. فتح مستند مرحّل يقرأ فقط؛ التصحيح بعكس مرتبط أو مسار قانوني مصرح، لا تعديل تاريخي صامت.
- **التقارير:** شبكة حقيقية تدعم تحديد الخلية والنطاق والنسخ المباشر TSV إلى Excel، اختيار الأعمدة، فرز/بحث، هيدر وتذييل ومجاميع، drilldown إلى المصدر، معاينة وPDF/Excel/طباعة عبر مسار Backend/Reporting مثبت؛ لا يُستخدم تصوير HTML كبديل غير مُختبر للرسوم المالي.

## 5. قيود المحاسبة والإيرادات والذمم — لا تفاوض

- الزبون والمورد قد يكونان **طرفًا واحدًا / بطاقة واحدة / حساب أستاذ واحد**، ويظهر الدور Both في قوائم البيع والشراء. لا تُعد تخصيص حسابين افتراضيًا أو تظهر كشفين منفصلين لهذا الطرف. لكن الأطراف التاريخية بحسابين تنتظر تسوية ومهاجرة صريحة من Claude، ولا تدمجها من الواجهة.
- كشف الطرف **زمني تفصيلي**: كل حركة مالية بسطرها المستقل (Date, posting sequence, source kind, source number, description, debit, credit, running balance, reversal link)، مع رصيد افتتاحي واضح وترتيب ثابت وحساب صحيح عبر pagination. عمليات القبض والمبيعات والمشتريات والدفع والمرتجعات والقيود تظهر بحسب ما ثبت في المصدر؛ لا تُحسب فواتير المخزون مرتين.
- دفتر الأستاذ الافتراضي المعتمد: `scope=one`, `period=year`, `sources=[sales,purchase,receipts,payments,journal]`, `detail=detailed`. يفتح **حوار خيارات قبل التنفيذ** لا تقريرًا فوريًا، ويعرض من دون اختراع معلمة غير موجودة. مصدر البيانات خادمي؛ أصدر بطاقة فجوة Backend إذا افتقدت فلترة المصادر؛ اختر خطة عرض صادقة فقط حتى يعالجها Claude.
- ميزان المراجعة: اختيار حساب أو فرع من الشجرة مع أبنائه، التصنيف، الفترة، مستوى التجميع، الصفر والحركة؛ المجاميع من Backend ولا تُضاعف الأرصدة الرئيسية والفرعية.
- كشف حساب الزبائن/الموردين يعرض في اختيار الطرف الأطراف التجارية المناسبة فقط؛ دفتر الأستاذ العام يستمر بدعم جميع حسابات COA، لا تمنعه من حسابات أخرى بالخطأ.
- سندات القبض والدفع واليومية والقيد تعمل **وفق الأنماط المنشورة وإصداراتها**؛ لا تختزل النمط إلى عنوان أو لون. الحساب الافتراضي والعملة والحقول والرقم والسياسات والتصفية والمصادقات وتاريخ القطع تأتي من `effective` الحقيقي.
- **قرار VP-024:** الموافقات مسموحة في كل أنماط Petra وفق قواعد الأمان الحالية، ولا تُنسخ قيود الأمين القديمة على اختيار مدين ودائن تلقائيًا.
- **«قيد لكل قلم» يبقى مؤجلًا** حتى اختبار مطابقة حقيقي موثق مع الأمين 10، ولا تحاكيه في UI كخيار يعمل. «القبض والدفع بعدة طرق» لا تُعلن أنها متاحة قبل وجود Backend مُختبر ومُصرح.
- الجرد، المخزون السالب، التسعير، فروقات الصرف، العملة الأساسية، ترحيل المستندات، الترقيم، إغلاق الفترات، والمطابقة: الحقيقة يقررها Backend، وReact مسؤولة عن إدخال صحيح وعرض واضح فقط.

## 6. الربط الحقيقي بالـAPI — لا تُنشئ واجهة ميتة

اعمل على طريقة **vertical slices**: اسم الشاشة → صلاحيات → عقد OpenAPI حي → Handler → DTO → Backend states → تنفيذ React → API query/mutation → حالات loading/empty/error/403/conflict → اختبارات UI + تكامل مع خادم TEST → screenshot → توثيق → Commit.

1. شغّل API أو افحص نسخة OpenAPI الفعلية، وقارنها بالمثبت `src/PetraERP.ApiClient/openapi/petraerp-v1.json`، ثم `npm run api:generate` و`npm run api:check`. لا تحرر `schema.d.ts` يدويًا.
2. استخدم typed client الموجود `src/services/api/client.ts` وTanStack Query مع query keys تشمل الشركة والسنة والفرع والمستخدم/بصمة الصلاحيات، مع عزل كامل وإبطال مناسب بعد الحفظ/التحديث، وإلغاء الاستعلام القديم؛ لا polling غير ضروري.
3. حافظ على إصدار API، أخطاء HTTP (400/401/403/404/409/422/500)، `ExpectedVersion`, `IdempotencyKey`, concurrency/conflict recovery، والتأكيد قبل عمليات العكس أو الحذف.
4. تحقق من كيفية اختيار الشركة قبل الدخول ونطاق token/tenant وWorkspace header على الخادم؛ لا تثق بقيمة في LocalStorage كي تمنح صلاحية أو تصل إلى بيانات شركة أخرى.
5. أرسل لـClaude فجوة موثقة داخل `docs/ai/FRONTEND_BACKEND_GAPS.md` بكل Endpoint ناقص: feature, current route/schema, missing fields, required contract, permission, validation, sample request/response **مقترح بوضوح وليس مُنفذًا**, acceptance tests, priority. وواصل الوظائف المستقلة.
6. لا تعدّل Domain/Application/Infrastructure/API من داخل فرع الواجهة دون التنسيق مع Claude؛ لا تعتمد Mock persistent responses لتعويض خدمة ناقصة. تعطيل الإجراء مع سبب صريح أفضل من نجاح وهمي؛ إن لم توجد وظيفة Backend فلا تسمها مكتملة إنتاجيًا.
7. خزّن tokens بأمان مناسب لبيئة Windows/Tauri، لا في `localStorage` نصي غير محمي، ولا تطبع رموز JWT أو Recovery Keys أو كلمات مرور في logs أو screenshots. اضبط CSP/permissions/URL allowlist بما يتفق مع خادم LAN الفعلي؛ لا تعطّل TLS verification لحل شهادة محلية.

## 8. أساس الأداء، UX والاستقرار

- أهداف قياس (لا تدّعِ تحقيقها قبل القياس): استجابة الحركات الداخلية فورًا دون انتظار الشبكة حيث لا أثر مالي، P95 لفتح بيانات الشاشة ≤500ms على LAN تجريبي مناسب عند API سليم، P95 للبحث المرجعي بعد debounce ≤350ms، تحريك 10,000 صف افتراضي دون تجميد محسوس، عدم انهيار UI عند 50 مستخدمًا (اختبار متكامل مع Backend مستقبلاً). إذا حالت بيئة الاختبار دون ذلك، سجل baseline ونتيجة فعلية وسبب التباين.

- اعزل أخطاء القطع/الإلغاء وتغيير الشركة أثناء البحث، التسلسل والتزامن، إعادة فتح مستند مع `ExpectedVersion`, وشاشة إدخال في وضع انقطاع الشبكة دون حفظ مزعوم.
- اختبارات الوصول keyboard/tab order/aria/menu focus/contrast، وتحميل الخطوط العربية الصحيح ونسخ أرقام عربية وإنجليزية بطريقة غير مكسورة.
