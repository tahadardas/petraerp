# تصنيف عمليات API بلا مستهلك Desktop (2026-11-17)

مبني على القائمة الآلية في [`API_WITHOUT_DESKTOP_SURFACE.md`](API_WITHOUT_DESKTOP_SURFACE.md) (21 من 298). لم تُنشأ أي شاشة: الغرض تحديد
ما يحتاجه المحاسب فعلاً مما هو إداري أو موجّه لوحدات وتكاملات. التصنيف من دلالة المسار والصلاحية، وليس قراءة تشغيلية للاستهلاك.

| الفئة | العمليات | الحكم |
|---|---|---|
| إدارة منصة/وحدات (مشرف النظام، ليس المحاسب) | `GET /modules`، `POST /modules/{id}/enable`، `…/disable`، `GET /system/write-gate` | تبقى API/CLI. واجهة مدير الوحدات في Desktop لم تُبنَ وتُؤجَّل إلى مرحلة الوحدات الاختيارية. |
| موجّهة للوحدات | `POST …/modules/{moduleId}/commands/{commandKey}` | عقد وحدات (SDK)؛ تستهلكه الوحدات المثبَّتة لا المحاسب. |
| ترحيل/تهيئة تركيب | `GET /workspaces/migration/plan`، `POST …/execute`، `…/branch-admin/{target}/sync-central`، `…/branch-admin/tree`، `…/branch-admin/{target}` | إداري/نشر (CLI). لا شاشة محاسب. |
| تصدير للتكامل | `GET …/reconciliation/export/json`، `…/export/csv` | للتكاملات/الأرشفة؛ شاشة المطابقة تعرض النتيجة. تصدير من الواجهة اختياري لاحقاً. |
| تفصيل مغطى بقوائم موجودة | `GET …/commercial-papers/{paperId}`، `GET …/calendar/fiscal-years/{fiscalYearId}`، `GET …/ledger/chart/accounts/deletions` | قراءات تفصيلية/تدقيقية؛ قائمتها أو بطاقتها تغطي العمل اليومي. مرشّحة لعرض داخل الشاشة القائمة (لا شاشة جديدة) إن طلب المالك. |
| **بيانات محاسبية يدوية بلا واجهة (قرار مالك)** | `GET/POST …/open-items`، `GET …/open-items/{id}`، `GET …/open-items/party-balances`، `POST …/opening-balances`، `GET …/opening-balances/{batchId}` | هذه هي الفئة الوحيدة المتصلة بعمل المحاسب (أرصدة افتتاحية وبنود مفتوحة). **لم تُبنَ لها واجهة هنا**: الأرصدة الافتتاحية تمرّ حالياً عبر ترحيل السنة والاستيراد، والبنود المفتوحة تظهر في التسويات. قرار بناء شاشة مدخل يدوي يعود للمالك؛ لا تُنشأ كنسخة مكررة. |

الخلاصة: 15 من 21 إدارية/وحدات/تكامل أو تفصيل مغطى، و6 (4 للبنود المفتوحة و2 للأرصدة الافتتاحية) بانتظار قرار المالك. لا تغيير في الكود.
