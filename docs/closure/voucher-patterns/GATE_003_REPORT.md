# AMN-VPAT-GATE-003 — سياسة الترحيل والموافقات (التقرير) · يتوقف للموافقة

**الأساس:** `b689c43`. **قرارات سابقة سارية:** المتعدد الطرق مؤجل؛ قاعدة «لا منح = لا أحد» معلّقة.

## القرار الهندسي المعتمد في هذه البوابة (policy)
1. **الشركة هي السقف:** سياسة الشركة (`DocumentPostingMode`) أمنية ولا يتجاوزها النمط (MASTER §6.1). لذا يستطيع النمط أن يكون **أشد** (يحتجز سنداته للترحيل اليدوي) ولا يستطيع أن يرحّل ما تحتجزه الشركة.
2. **الموافقة منفصلة عن الترحيل:** الترحيل الآلي لا يختصر الموافقة المطلوبة؛ يبقى `treasury.approval_required` عند غيابها.
3. **الموافقة بحد مبلغ:** كانت `ThresholdAmount` تعمل في المبيعات فقط؛ صارت تعمل في السندات بالمقارنة نفسها (`المبلغ ≥ الحد`، بعملة المستند) لتوحيد السلوك (خطر R12).

## ما نُفِّذ

## ما لم يُنفَّذ عمداً (يحتاج موافقتك + هجرة) — معاينة الهجرة
**أ) قيد لكل قلم (`PerLineJournal`, VP-015):** السند يحمل `JournalEntryId` واحداً (`VoucherRow`)، والتقارير تربط المصدر به (`SqlProfessionalReportService.Sources.cs:26-27`)، والعكس بعكس قيد واحد. قيد لكل قلم يعني عدة قيود لسند واحد، فيلزم:
```
CREATE TABLE treasury.VoucherJournalLinks (VoucherId uniqueidentifier NOT NULL FK→Vouchers, LineId uniqueidentifier NOT NULL, JournalEntryId uniqueidentifier NOT NULL FK→JournalEntries, ReversalJournalEntryId uniqueidentifier NULL, CONSTRAINT PK PRIMARY KEY (VoucherId, LineId));
-- الصفوف القديمة: لا شيء (JournalEntryId الحالي = قيد مجمع). لا تعديل لقيد مرحَّل.
```
وتغييرات في الترحيل (إنشاء N قيود ذرياً بمفتاح idempotency واحد وأرقام مشتقة)، والعكس (عكس كلها أو لا شيء)، وSources.cs (UNION على الجدول). **لم أنفّذه:** يمس الترحيل والتقارير ولا أريد وعداً غير مكتمل. خيار `PerLineJournal=true` يبقى مرفوضاً (يفشل مغلقاً).

**ب) مصادقات متعددة الخطوات (VP-023):** مستخدمون وتسلسل وشروط مبلغ تحتاج تخزين قرار كل خطوة:
```
CREATE TABLE patterns.ApprovalSteps (Id, PatternRevisionId FK, StepOrder int, UserId NULL, RoleId NULL, MinAmount decimal(19,4) NULL);   -- يخص النسخة المنشورة (لا يُعدَّل بعد النشر)
CREATE TABLE treasury.VoucherApprovals (Id, VoucherId FK, StepId FK, ApprovedByUserId, ApprovedAtUtc, Reason);                           -- سجل قرار كل خطوة
```
يتبعه تغيير `/approve` ليكمل خطوة المستخدم الحالية فقط وتحقق الترحيل من اكتمال الخطوات، وتعليق العكس على موافقة جديدة (VP-026). **لم أنفّذه** لنفس السبب.

**ج) `AutoPost` (الترحيل لحظة الاعتماد):** يحتاج خطّاف حدث اعتماد؛ يبقى مرفوضاً.

## قرارات أحتاجها منك
1. **VP-024 (قيد الأمين):** الأمين لا يسمح بالمصادقة على نمط فيه حقلا مدين ودائن معاً. هل نحاكيه أم نسمح بالموافقات في كل الأنماط؟ (لم أفترض شيئاً.)
2. هل أنفّذ **أ) قيد لكل قلم** و**ب) المصادقات المتعددة** بالهجرتين أعلاه (بعد معاينة SQL الفعلية ونسخة احتياطية واستعادة تجريبية)، أم تؤجلهما؟
3. الموافقة على GATE-003 كما هو، ثم الانتقال إلى GATE-004 (المتعدد الطرق، وهو مؤجل بقرارك) أم GATE-005 (شاشة إدارة الأنماط)؟

## Rollback
عكس Commit البوابة. لا هجرة SQL. `PostingMode` افتراضه الحالي فلا يتأثر نمط قائم.
